Reference

Reading primer

A five-minute refresher on the ideas you'll use. Skim it now; come back to any part during the rounds.

1 · Storage — type, tier & querying

  • Type: object (a warehouse of labelled boxes — files, images, backups, data lakes), block (a hard-drive for one server — databases), file (a shared network drive).
  • Tier: hot (frequent, dearest) → cool (infrequent) → archive (rare, cheapest, slow to retrieve). Tiering is the biggest storage-cost lever; lifecycle rules move ageing data down automatically.
  • Query: SQL for structured tables, NoSQL for flexible data at scale, a data warehouse for cleaned reporting, a data lake + query-in-place for raw everything, and a search index to find things fast. How you store shapes what you can ask. Watch egress — moving data out can cost more than storing it.

2 · Cloud search

  • A search engine is not a database query. It builds an inverted index (word → items) so it can find things in milliseconds and rank them by relevance.
  • Good search is typo-tolerant ("buter" → butter), knows synonyms & units, offers facets/filters, ranks in-stock & popular items up, and suggests via autocomplete. Semantic search matches meaning, not just words.
  • Relevance is a revenue lever — a plain database "LIKE" query silently loses every misspelled search.

3 · Cost-effective data warehousing

  • A warehouse is built for analytics (OLAP) — big questions across all your data — not for running the live app (OLTP). Never run heavy analytics on the live database.
  • The cloud trick: separate storage from compute. Data sits cheaply; compute "warehouses" spin up only to run queries. So idle compute is pure waste.
  • Cost levers: auto-suspend (turn compute off when idle), right-size (smallest that answers in time), partition/prune, columnar formats, caching, materialized views.

4 · Subscribing to third-party data

  • First-party = your own data; second-party = a partner's, shared directly; third-party = bought from a specialist (weather, demographics, market, geospatial) to fill the gaps.
  • Modern data marketplaces let you subscribe to a live share — you query the provider's data in place, always fresh, no copy and no egress.
  • Before subscribing, check the licence (does it permit your use?), privacy (personal data triggers India's DPDP Act), freshness, and value vs price. A clean room lets you combine sensitive data without exposing raw records.

5 · Real-world anchors

Concrete examples you can bring into the debate — all widely reported:

  • Storage/egress — 37signals: the maker of Basecamp publicly left the cloud, reporting that at its steady scale owning hardware was far cheaper — with data-transfer (egress) among the costs that add up. Cloud is usually cheaper to start, but at steady scale the economics can flip. Keep measuring.
  • Search — the OpenSearch fork: in 2021 AWS forked Elasticsearch into OpenSearch after a licence change. Managed search services (OpenSearch, Azure AI Search, Algolia) run the index for you — but watch the licences behind your tools.
  • Warehousing — Snowflake & BigQuery: a generation of cloud warehouses grew by separating storage from compute and charging per query/per second — turning always-on idle spend into a switch you control.
  • Third-party data — weather for retail: retailers have long blended weather data into demand and staffing decisions. Marketplaces now list thousands of datasets, and clean rooms let parties combine sensitive data without exposing raw records.

Round 2 — how the score is built

With every feature off, the query "organic buter 500g" is matched literally, so the typo "buter" matches nothing — zero results. That's the whole point: a plain database query silently loses the sale.

FeatureAddsWhat it does for this query
Typo tolerance+30"buter" now matches "butter" — the butters finally appear. The single biggest fix.
Relevance ranking+20Boosts in-stock & popular items; pushes the false match "Butter Chicken Masala" down.
Synonyms & units+10Understands 500g / half-kg and local terms so more true matches surface.
Facets & filters+10Lets the shopper narrow by brand, price, organic — fewer dead ends.
Autocomplete+10Catches the typo before the search runs, suggesting "organic butter 500g".
Semantic / vector+5Surfaces meaning-based matches (e.g. organic dairy) even without the exact words.
Teaching point: the model config turns everything on for a score near 100 and puts Organic Butter 500g at #1. But the lesson isn't "toggle everything" — it's that typo tolerance and relevance ranking do most of the work, and that a search engine solves problems a database query cannot. Relevance is a revenue lever: every one of those recovered searches is a recovered sale.

Round 3 — a sensible config, and the saving

The waste isn't storage — it's a big warehouse left on. Right-size and switch on auto-suspend:

StepConfigMonthly cost
TodayLarge, 24 h/day₹11.52 L
Right-sizeMedium, 24 h/day₹5.76 L

Result: a Medium warehouse that only runs when it's needed costs about ₹1.9 L/month vs ₹11.5 L — roughly ₹1.15 Cr saved a year (~83%), for the same dashboards. Teaching points: (1) idle compute is the biggest waste — auto-suspend resumes in seconds, so "always on" buys almost nothing; (2) right-size to the job, and scale up only for a heavy one-off load, then back down; (3) partitioning, columnar formats, caching and materialized views cut the bill further by scanning less data. Formula: monthly = credits/hr × ₹200 × hours/day × 30.

Round 4 — facilitating the decision

The model call is Subscribe with conditions (treating the PII light as a hard gate). The deal is strong — good licence, live share with no copy, fair value, trusted provenance — but the household-level personal data is a real DPDP risk and must not be used raw. The fix is known: take only aggregated demographic fields, or combine the data in a clean room. The yearly-demographics freshness is a minor limitation you accept (demographics move slowly); the daily weather is what the forecast really needs. A flat Decline throws away a valuable, fixable deal; a plain Subscribe that ignores the red light is the weakest answer.

Quick glossary

Object / block / file
Storage for files & images / server & DB disks / shared network drives.
Hot / cool / archive
Storage tiers from frequent-and-dear to rare-cheap-and-slow.
Lifecycle rule
Automatic policy that moves ageing data to cheaper tiers.
Egress
Data-transfer-out fees — getting data out can cost more than storing it.
Query-in-place
Running SQL over files where they sit, without loading them into a database.
Data lake
Raw data of every kind kept cheaply (schema-on-read) for later use.
Data warehouse
Cleaned, modelled data organised for fast business reporting (OLAP).
Lakehouse
Warehouse-style tables directly on the lake — one copy for BI and data science.
OLTP / OLAP
Transactions (running the live app) vs analytics (big questions across data).
Inverted index
A word → items map that lets search find things instantly.
Relevance ranking
Ordering search results by how well they match — a revenue lever.
Typo tolerance
Fuzzy matching so "buter" still finds "butter".
Facet / filter
Narrowing results by brand, price, rating and the like.
Semantic / vector search
Matching meaning, not just words ("summer drink" → lemonade).
Separate storage & compute
Cloud warehouses store data cheaply and bill compute only while queries run.
Auto-suspend
Turning warehouse compute off when idle — the biggest warehouse saving.
Right-size
Choosing the smallest warehouse that answers in acceptable time.
Partition pruning
Storing data by date/region so a query scans a slice, not the whole table.
ELT
Load raw data first, then transform it inside the warehouse.
First / second / third-party data
Your own / a partner's shared directly / bought from a specialist.
Data marketplace
A catalogue where you subscribe to external datasets.
Live data share
Access to a provider's data in place — always fresh, no copy, no egress.
Clean room
A safe space to combine sensitive data without either side seeing raw records.
PII / DPDP Act
Personal data / India's Digital Personal Data Protection Act (2023) governing it.
