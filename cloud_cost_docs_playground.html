BrightBasket — a grocery-delivery startup with a scary bill

BrightBasket delivers groceries in 40 minutes. Growth is great; the cloud bill tripled in three months and nobody can say why. Reference

60-second refresher

The ideas you'll use. Skim now; come back during the rounds.

The billing machine

Usage is metered (per second · GB · request) → a rate is applied (on-demand, discounts, commitments) → charges roll up into an invoice per account → tags/labels split that invoice back to teams. You read it in one cost console per cloud: Cost Explorer Cost Management Cloud Billing

The account hierarchy

  • Spend container — where resources live & the bill splits. Account Subscription Project
  • Grouping — nest containers by team / environment. Organizational Units Management groups Folders
  • Guardrails — stop bad spend before it happens. SCPs Azure Policy Org policies

The four ways to pay

  • On-demand — pay per second, no commitment. Best for unpredictable, spiky work.
  • Commitment (1–3 yr) — up to ~70% off for a steady baseline. Savings Plans / RIs Reservations CUDs
  • Spot — up to ~90% off spare capacity, can be reclaimed. Best for restartable batch jobs.
  • Rightsize / kill — the cheapest server is the one you turned off. Idle resources are the #1 waste.

The four doc types (Diátaxis)

  • FAQ / Explanation — the recurring questions and the "why", answered once.
  • Runbook — step-by-step for a recurring task ("investigate a cost spike").
  • How-to — goal-oriented steps ("tag a resource", "set a budget alert").
  • Reference — look-up facts & tables (the Rosetta Stone of names and owners).

A good FAQ uses the real questions people ask, answers first then details, links out to the deep doc, and names an owner. Untagged spend is unallocatable spend — tag from day one.

Discussion · 2 min

Round 1 — teaching point

Warm-up recognition of the Rosetta Stone. If a team scores low, send them back to the deck's cheat-sheet slide before Round 2. The traps are the look-alikes: Savings Plans (AWS) vs Savings plans (Azure) — both exist; the tell is the surrounding term. Spot Instances is the AWS name, while Azure and GCP both say Spot VMs. Only GCP has an automatic Sustained Use Discount.

Teaching point: the classic slip is answering "tag it" for everything. Tags allocate spend; they don't stop it (that's a guardrail) or warn you (that's a budget or anomaly alert). Separating prod/staging/dev is structural, not a tag. A real setup uses all six.

Teaching point: commit to steady, already-rightsized load; use spot for interruptible batch; keep on-demand for the unpredictable; and rightsize/kill before you do anything else — committing to an oversized box just locks in the waste.

Round 4 — model doc types (Diátaxis)

Recurring questionModel doc typeWhy
"Why did our bill jump $8k last month?"RunbookA repeatable investigation procedure — same steps every spike
"How do I tag my resources so they bill to my squad?"How-toGoal-oriented steps for one concrete task
"What's Azure's name for a Savings Plan?"ReferenceA pure look-up — the Rosetta Stone table

Teaching point: mixing types is the number-one documentation mistake. A how-to buried inside an explanation helps no one. The meta-lesson for BrightBasket: most of Dana's interruptions are a missing doc, not a hard problem — write it once and the question stops coming.

Reference

Glossary

The terms in play, in one place — the kind of "reference" doc every team should keep.

TermWhat it means
On-demandPay per second/hour with no commitment. Most flexible, most expensive at scale.
Commitment1- or 3-year discount for steady usage. Savings Plans / RIs Reservations CUDs
SpotDeep discount on spare capacity that can be reclaimed at any time. For interruptible work.
Sustained Use DiscountGCP-only automatic discount for VMs run a large part of the month — no action needed.
Tag / LabelKey–value metadata on a resource used to allocate cost back to a team or project.
Showback / ChargebackShowback shows a team its bill; chargeback makes them pay it. The lever for accountability.
Budget & alertA spend threshold that warns you as you approach it. Caps surprise, not spend itself.
Anomaly detectionAutomatic alerting when spend suddenly deviates from the normal pattern.
GuardrailA policy that prevents bad spend. SCPs Azure Policy Org policies
FinOpsThe practice of running cloud as a business: Inform → Optimize → Operate, as a continuous loop.
FOCUSThe FinOps Cost & Usage Specification — a common billing-export format across all three clouds.
EgressData leaving the cloud or crossing regions. Metered; inbound is usually free. A classic surprise.
RightsizingShrinking (or killing) resources to match real usage. Usually the fastest saving.
DiátaxisA framework sorting docs into tutorial, how-to, reference and explanation — keep them separate.
