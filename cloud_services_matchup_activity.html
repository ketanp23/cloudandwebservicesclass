Reference

60-second refresher

The ideas you'll use. Skim now; come back during the rounds.

The one big idea

Every provider sells the same ~10 categories of service under different names. Learn the category and the provider's brand name is just vocabulary.

The compute shapes

  • Virtual machine — a whole server you control & patch. Best for lift-and-shift and full control. EC2 Azure VMs Compute Engine
  • Container — an app packaged to run identically anywhere; portable across clouds (Kubernetes). EKS AKS GKE
  • Serverless function — code that fires on an event; pay per run, no servers. Lambda Functions Cloud Run functions

The data shapes

  • Object storage — files, images, video, backups. S3 Blob Cloud Storage
  • Relational (SQL) — structured, transactional data (orders, payments). RDS Azure SQL Cloud SQL
  • NoSQL — huge scale, flexible schema (catalogs, carts). DynamoDB Cosmos DB Firestore
  • Data warehouse — analytics across huge datasets. Redshift Synapse / Fabric BigQuery

Names change — Azure AD is now Microsoft Entra ID; Azure AI Foundry is now Microsoft Foundry. When in doubt, reach for the deck's cheat sheet.

Round 1 — teaching point

This is warm-up recognition. If a team scores low, they haven't internalised the cheat sheet yet — send them back to the deck's Rosetta Stone slide before Round 2. The traps are the look-alikes: Cloud Storage (GCP) vs Blob Storage (Azure) vs S3 (AWS), and Cloud Run (GCP) vs Container Apps (Azure).

Round 2 — model stack for StreamKart

NeedModel categoryExample service
Handle spiky live-stream storefront trafficCompute — containers / serverlessFargate · Container Apps · Cloud Run
Store product images & recorded videoObject storageS3 · Blob · Cloud Storage
Orders & payments (must be consistent)Relational databaseRDS/Aurora · Azure SQL · Cloud SQL

Deliver video fast to viewers worldwideContent delivery (CDN)CloudFront · Front Door · Cloud CDN

Teaching point: the classic slip is putting video only in object storage and forgetting the CDN — storing ≠ delivering fast. Orders belong in SQL (consistency); the high-scale catalog fits NoSQL. A real stack mixes categories, not providers.

Round 3 — model compute shapes

WorkloadModelWhy
Generate a thumbnail whenever a video is uploadedServerlessEvent-driven, short, spiky — pay per run
Lift-and-shift a legacy app that needs a specific OS & licenceVMFull OS control; no re-architecting
A microservice you want to move between clouds next yearContainerPortable via Kubernetes; avoids lock-in
A nightly 3-minute report jobServerlessRuns briefly on a schedule; idle cost = 0
An always-on app with a large, steady database serverVMConstant load; serverless would cost more
A steady web API you want packaged & portableContainerConsistent runtime, easy to scale out

Teaching point: serverless shines for spiky/short/event work; VMs for control and steady load; containers for portability. "Steady + always-on" is the tell that serverless may cost more, not less.
